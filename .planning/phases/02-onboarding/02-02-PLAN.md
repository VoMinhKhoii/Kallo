**2. Create `lib/onboarding/actions.ts`** — `'use server'` directive at top:

`getOnboardingProfile()`
- Auth: `createClient()` → `supabase.auth.getUser()`. Throw if no user.
- Query: `db.select().from(userProfiles).where(eq(userProfiles.userId, user.id)).limit(1)`
- Return `rows[0] ?? null`

`saveOnboardingScreen(step: number, data: Record<string, unknown>)`
- Auth: get user, throw if none.
- **Fetch current row first** (needed for max-step logic + fallback defaults):
  ```ts
  const [existing] = await db.select({
    onboardingStep: userProfiles.onboardingStep,
    onboardingCompletedAt: userProfiles.onboardingCompletedAt,
    handSpanCm: userProfiles.handSpanCm,
    knuckleDepthCm: userProfiles.knuckleDepthCm,
  }).from(userProfiles).where(eq(userProfiles.userId, user.id)).limit(1);
  ```
- Compute `newStep = Math.max(existing?.onboardingStep ?? 0, step)`
- Build base update: `const updateObj: Record<string, unknown> = { onboardingStep: newStep }`

- **Step-specific field mapping:**

  Step 1:
  ```text
  weightKg, heightCm, age, biologicalSex, activityLevel, tdeeKcal,
  goal, aggression, carbSplit,
  calorieTarget: Math.max(data.calorieTarget, 500),  // Floor guard
  proteinTargetG, carbsTargetG, fatTargetG
  ```

  Step 2: `regionalProfile`

  Step 3: `handSpanCm, knuckleDepthCm`

  Step 4 — **cooking habits**:
  ```text
  oilUsage, defaultRicePortion, sugarBraised,
  defaultProteinPortion, brothConsumption
  ```

- **Completion + fallback defaults:**
  ```ts
  if (newStep >= ONBOARDING_REQUIRED_STEP) {
    if (!existing?.onboardingCompletedAt) {
      updateObj.onboardingCompletedAt = new Date();
    }
    // Apply SKIP_FALLBACK_DEFAULTS for hand measurement fields still null
    if (!existing?.handSpanCm) updateObj.handSpanCm = SKIP_FALLBACK_DEFAULTS.handSpanCm;
    if (!existing?.knuckleDepthCm) updateObj.knuckleDepthCm = SKIP_FALLBACK_DEFAULTS.knuckleDepthCm;
  }
  ```

- Execute: `await db.update(userProfiles).set(updateObj).where(eq(userProfiles.userId, user.id))`
- Return `{ success: true }`

Create `components/onboarding/screen-body-metrics.tsx` — `'use client'`.

**Type + merged schema** (define at top of file):
```ts
import { bodyMetricsSchema, goalSchema } from '@/lib/onboarding/schemas';

const screen1Schema = bodyMetricsSchema.merge(goalSchema);
type ScreenOneData = z.infer<typeof screen1Schema> & { tdeeKcal: number };
```

**Props:** `{ defaultValues: Partial<ScreenOneData>; onChange: (data: ScreenOneData) => void }`

**Form setup:**
- `useForm<z.infer<typeof screen1Schema>>({ resolver: zodResolver(screen1Schema), defaultValues, mode: 'onBlur' })`
- **mode: 'onBlur'** prevents validation on every keystroke for number inputs
- Use `watch()` internally ONLY for local TDEE computation
- Call `onChange` on: field blur (for number inputs), immediate change (for select/radio — sex, activityLevel, goal, aggression, carbSplit). NOT on every keystroke.

**Section 1: Body Metrics Form** (top)
- **Biological Sex**: RadioGroup (Male / Female)
- **Weight (kg)**: Number input, placeholder "70"
- **Height (cm)**: Number input, placeholder "170"
- **Age**: Number input, placeholder "25"
- **Activity Level**: Select with 4 options + descriptions:
  - Sedentary — "Little or no exercise, desk job"
  - Lightly active — "Light exercise 1-3 days/week"
  - Moderately active — "Moderate exercise 3-5 days/week"
  - Very active — "Hard exercise 6-7 days/week"
- Soft validation hint: if TDEE < 800 or > 5000, show `<p className="text-sm text-muted-foreground">These numbers look unusual — double-check your inputs</p>` under results
- After results visible: `<p className="text-sm text-muted-foreground">Something look off? Adjust above</p>` above the metrics section

**Section 2: TDEE Results** (visible when all 5 body metrics are valid)
- Compute reactively from watched values:
  ```ts
  const values = watch();
  const allFilled = values.biologicalSex && values.weightKg && values.heightCm && values.age && values.activityLevel;
  const bmr = allFilled ? calcBMR(values) : null;
  const tdee = bmr ? calcTDEE(bmr, values.activityLevel) : null;
  ```
- Display BMR and TDEE when computed
- Mifflin-St Jeor formula in Collapsible

**Section 3: Reference Matrix** (visible when TDEE computed)
- **Label: "Shown at moderate pace — adjust below"**
- 3×3 grid: Maintenance/Cutting/Bulking × Moderate/Lower/Higher Carb
- All 9 cells use `calcDailyTargets(tdee, rowGoal, 'moderate', colCarbSplit)` — always 'moderate' aggression for reference
- Each cell: Calories | P: Xg | C: Xg | F: Xg
- Currently selected goal × carbSplit highlighted with ring/accent
- Click cell → `setValue('goal', rowGoal)` + `setValue('carbSplit', colCarbSplit)`
- Use `useMemo` to compute all 9 cells (recompute only when TDEE changes)

**Section 4: Fine-tuning** (visible when goal is 'cutting' or 'bulking')
- **Aggression Level**: 3 radio buttons with rate labels:
  - Gentle — ~0.25 kg/week (~275 kcal/day)
  - Moderate — ~0.5 kg/week (~550 kcal/day)
  - Aggressive — ~0.75 kg/week (~825 kcal/day)
- **Deficit/Surplus Override**: Number input (50-1500 range)
  - Initialize from AGGRESSION_PRESETS[currentAggression]
  - On aggression change: reset override to new preset
  - On direct edit: update override, leave aggression unchanged
- **Live Final Targets**: `calcDailyTargets(tdee, goal, aggression, carbSplit, deficitOverride)`
  - Display: Calories kcal | Protein g | Carbs g | Fat g

For 'maintaining': hide Section 4. Final targets = maintenance row from matrix.

**onChange reporting** (to wizard-shell):
- Subscribe to form changes via `watch()` callback
- Call onChange only on discrete events: radio/select changes (immediate), number inputs (on blur)
- Include computed tdeeKcal in the reported data

**Tailwind layout:**
- Desktop: `lg:grid lg:grid-cols-2 lg:gap-8` (form left, results right)
- Mobile: stacked single column
- Use shadcn Card for matrix cells, RadioGroup for selections, Input for numbers, Select for activity level
